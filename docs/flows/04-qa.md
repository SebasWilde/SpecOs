## Notes

- There is no status field. A case with `steps:` is expanded; one without is a sketch.
- `spec: v1.1` records which spec version QA reviewed. `/specos-status --check` warns when the spec moves ahead of it.
- Findings are routed: a code defect becomes a bug text citing the case and the AC; a spec gap becomes a change request; a bad case is fixed.
- Case count targets, negative cases and batching come from `settings.qa`. `cases_per_ac` is the target the agent tops up to — sketches already count toward it.
- Test case IDs use the prefix in `specos-project.yml` (default `TC`); new cases continue from the highest id.
